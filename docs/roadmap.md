# 小途路线图

当前主线是 FastAPI + LangChain/LangGraph 和已有网页；地图与铁路是只读旅行工具，模拟外卖用于验证写操作的可靠执行，不是产品预订能力。实现位置与 API 见[开发指南](development.md)。

| 顺序 | 交付目标 | 验收条件 |
| --- | --- | --- |
| 1. 建好协作基线 | 私有主仓、模块负责人、保护分支、合并检查 | 新成员用干净检出和空配置可以运行测试与演示。规则见[协作约定](../CONTRIBUTING.md)。 |
| 2. 提升规划质量 | 积累澄清、地点核实、天气覆盖、城际和市内交通衔接的回归场景 | 用户能辨认证据来源、未核实项目和推荐替换；保持调用预算与锁定地点。 |
| 3. 在线网页与 App | 服务端行程 ID、版本、身份、数据隔离及 HTTPS API；App 复用同一 API | 同一用户跨设备恢复；不同用户无法互访；并发编辑提示冲突；有备份及回滚。不把模型密钥和 Node 子进程放进 App。 |
| 4. 新供应商与代办 | 先接酒店、门票、用车等只读查询和估价，再评估真正预订、取消 | 联系经过授权的供应商；明确价格、时效、用户确认和查单能力。结果未知时不换键重下单；无幂等或核验能力时不自动重试写入。 |

[弱网实验](reliable-tool-experiment.md)可与规划优化并行，但模拟成功不等于第三方生产环境能提供同样保证。12306 首版继续采用 Python MCP 客户端启动服务端 stdio 子进程；后续再评估合规的托管 MCP 或其他供应商。

当前不依赖 AgentArts 托管。是否做赛道专用平台方案单独评估，不把本地演示当成平台部署，不长期维护两套相互独立的业务主流程。
