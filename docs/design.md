# 小途前端设计

小途用一句旅行需求作为入口。海盐白、墨绿、天空蓝和原创山海插画构成轻量背景；正文以系统中文字体为主，不加载远程字体。桌面保留旅行概览，窄屏使用底部导航。当前为原生 HTML/CSS/ES module，与后端通过同源 API 解耦。

## 页面与交互

| 页面 | 交互 |
| --- | --- |
| 与小途聊聊 | 普通聊天和查询不修改已有行程；天气和铁路卡片随原回复显示，不跳页。空态建议横向滚动；点击只填入输入框。Enter 发送，Shift+Enter 换行，中文输入法组合期间不发送。 |
| 我的行程 | 分日时间轴、可核实的地点和路线、出发条件编辑、地点替换与调序预览。未核实的点不参与线路展示；定位失败给重试或手填；日历导出前明确确认。 |
| 旅行账本、旅行偏好 | 区分估算和实际记账；从对话抽取的偏好经用户确认才保存。 |
| 数据与连接 | 区分已配置和实际查询结果，提供独立查票入口。开启实验时，顶栏显示模拟外卖。 |

## 文件和数据

- `public/index.html`、`styles.css`：应用壳、设计变量及移动端布局；`app.js`：页面状态、聊天、账本和偏好。
- `departure.js`、`rail-query.js`、`location.js`：出发条件、铁路查询与浏览器定位；缺起点时行程卡可尝试获取城市，具体坐标不在前端持久保存。
- `trip-map.js`、`place-editor.js`：地图、同城地点搜索与编辑预览；`food-order.js`：模拟外卖的报价、明确确认和查询原订单结果。
- `chat-cards.js` 会渲染外卖分支的卡片（菜单、门店、地址、优惠券、订单、报价单）；报价卡上的「确认下单」是唯一的下单入口，成功后返回 `#/order/<报价标识>` 路由打开订单详情视图。导航组件不设外卖入口，建议栏提供「帮我点份外卖」。
- `xiaotu.workspace.v1` 保存偏好、旅行、草案和账本；聊天记录只在页面内存。浏览器源切换时不共享草案。后台接口与测试见[开发指南](development.md)。

## 品牌与扩展

启动服务后访问 `/logo-concepts.html` 评审三组本地 SVG。应用仍用 A「一叶有途」作为暂定 Logo，B/C 仅作比较，不是定稿；未做商标查重。插画和标志在 `public/assets/`。

后续若适配 App，可保留设计变量和 SVG，优先复用地区、预算、行程及确认状态的接口约定；改成本地多行程或云同步时，先为现有浏览器草案设计迁移。
